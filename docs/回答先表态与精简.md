# 回答先表态与精简

## 背景

测试时回答显得“不直接”。对照 [PR #7 真实模型记录](verification/pr7-live-20261015/report.md)，原因有四个：

1. **第一句套模板**：提示词只给了时机题和 A/B 题的开头写法，模型把其它问题也写成“有条件适合，前提是……”。问“会有好事还是坏事”“今天运势怎么样”“行运对项目有什么影响”，第一句都是“有条件适合”。
2. **写作边界被讲给用户**：事实边界（相位日期不是现实事件日期等）本是写给模型的约束，模型却把它们写进正文，如“这个时刻不能当作现实事件发生时间”“这张牌不能用来判定……”。
3. **篇幅与铺垫**：要求“像资深命理师写信”、3-5 层、每层 200-400 字；正文常先写一层“排盘基准”，复述四柱、起运和口径。
4. **重复确认**：用户已写明起止日期，多 Agent 仍追问“是否包含首尾两日”。

## 改动

只改表达层，事实层校验不变。

| 位置 | 改动 |
|---|---|
| `agents/orchestrator.py` 写法 | 第一句按问题类型先表态，不超过 40 字，不写“前提是”；“有条件适合”只用于适不适合类问题且有一个决定性前提；前提放第二句起。sections 改为 2-3 层、每层约 150-250 字；advice 2-4 条；不单独写“排盘基准”层 |
| `agents/orchestrator.py` 事实边界 | 说明边界是写作约束，不向用户逐条解释；出生时间未知的不确定性、timeline 的人为安排，以及就医提醒、姓名写法确认、未收录意象照常写 |
| `agents/orchestrator.py` 流程 | 日主、起运、首步大运只在用户问到时写；口径约定一句话说明；用户写明的起止日期直接使用（含首尾两日），不再确认 |
| `agents/specialists.py` | 专家 answer 先给判断，再写最主要的一个前提 |
| `common/schemas.py` | `submit_reading` 字段说明与上面一致（schema 上限仍为 6 层） |
| `common/validation.py` | 两条新警告，只记录不打回：第一句含“前提”；非适不适合类问题、非二选一时第一句用“有条件适合” |
| `scripts/compare_layers.py` | 新增 `hedged_first`、`avg_caveats`、`basis_sections` 三项指标，从已保存的 rows 计算，旧 results.json 可直接重新出报告；首轮追问沿用已有的 `clarified` |

不改：事实校验、确定性说法禁令、就医与安全规则、回复末尾的“解读置信度：低”和“仅供参考与自我反思”（释义尚未人工审核，如实显示）、审校、渲染顺序、离线演示模型。

## 验收

离线测试只能确认警告和指标逻辑，不能证明模型照做。改动效果需要真实模型对照，题目、合成资料、日历基准和 seed 都与基线相同：

```powershell
& .\.venv\Scripts\python.exe scripts/compare_layers.py run --root . --label direct --mode single --model gpt-6.1-sol
& .\.venv\Scripts\python.exe scripts/compare_layers.py run --root . --label direct --mode multi --model gpt-6.1-sol
& .\.venv\Scripts\python.exe scripts/compare_layers.py report docs/verification/pr7-live-20261015/new-single reports/compare/direct-single docs/verification/pr7-live-20261015/new-multi reports/compare/direct-multi
```

预期：`hedged_first`、`avg_caveats`、`basis_sections`、`clarified` 下降；`avg_reply_chars` 约 800-1000；`rejections` 不上升。仍需按报告里的人工检查逐题阅读。

## 风险

- 篇幅收紧可能回到 PR #7 之前“只有一句结论”的问题；分层结构保留，只压长度。
- 正文不再解释边界后，模型可能写出越界说法；事实校验会打回，对照表的 `rejections` 可以看到是否上升。
