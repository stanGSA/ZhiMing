# 回答说白话

## 背景

网页测试八字时，回答让人看不出结论。以一次大运问题的回答为例：

1. **术语太多**：小标题是“当前大运：丁酉，与下一步的交界”，正文是“戊土为七杀、戊土藏戊为七杀根”“丁火为正财，酉金为印星”，还解释了“三天折一年、时辰差折算月日”的起运算法。不懂命理的用户得先把术语翻译一遍，才能看到对自己意味着什么。
2. **正文出现字面的 `<br>`**：模型按“分行写潜在挑战和潜在机遇”写了 HTML 换行标签，而聊天气泡和解读面板都按纯文本显示。

原因在提示词：示范的小标题本身就是术语（“核心碰撞：辰戌相冲”“能量压制：财生七杀”），body 要求“讲清这组关系是什么”；没有说明读者不懂术语，也没有规定换行怎么写。

## 改动

只改表达层，事实层校验不变。

| 位置 | 改动 |
|---|---|
| `agents/orchestrator.py` 写法 | 开头说明读者不懂命理、不认识术语也要能看懂结果；summary 用白话；title 写“这一层对用户意味着什么”，示例换成白话，不在标题放干支、十神或相位名称；body 先写结论和生活中的表现，再用一句话交代依据 |
| `agents/orchestrator.py` 新增规则 | 术语：summary、标题、advice、closing 不用术语，正文每层最多一两个且紧跟白话解释，专家报告和释义里的术语翻成白话再写。不讲推算方法：起运折算、大运顺逆、真太阳时修正等用户问到时只说结果，算法细节放进 evidence。换行直接换行，不写 `<br>` 或 Markdown 符号 |
| `agents/orchestrator.py` 传统推理、协作流程 | 十神生克等推理写给用户的是白话结论；多 Agent 融合专家 analysis 时把术语翻成白话 |
| `common/schemas.py` | summary、`Section.title`、`Section.body` 的字段说明与上面一致 |
| `common/output_policy.py` | `clean()` 把 `<br>`、`<br/>`、`<BR />` 换成真实换行，与删免责声明一样属于自动修正；专家报告同样处理 |
| `common/validation.py` | 新增警告，只记录不打回：summary、小标题、advice、closing 出现十神、干支、地支冲合、相位或宫位编号；用户自己问到的术语不计 |
| `scripts/compare_layers.py` | 新增 `avg_jargon`（整条回复的术语次数）和 `avg_lead_jargon`（结论、标题、建议、收尾里用户没问到的术语次数）；人工检查清单加“说白话” |

不改：事实校验（写出的干支、十神仍须与排盘一致）、专家提示词（专家报告是给编排者的素材，可以用术语）、evidence 附录（想看术语的用户可以展开“解读依据”）、渲染顺序、离线演示模型。

已保存的旧记录不回写，其中的 `<br>` 仍按原文显示。

### 评审后的边界修复

- 用户明确询问四柱、首步大运、十神、宫位或相位等结果时，允许回答必要的专业名称或计算值，再附白话解释。用户不需要先在问题中写出尚未知晓的“己未”等答案；其他无关术语仍记录警告，事实校验照常执行。
- 换行规范化补齐 `timeline.period`、`tensions.theme` 和最终解读及专家报告的 `confidence.reason`。元数据只转换换行，保留审核状态等说明，不套用正文删句规则。
- 对照结果新增 `question_context`，保存与运行时警告相同的原问题和当前消息语境。旧结果按同一场景此前的问题推断，报告中的 `inferred_jargon_context_turns` 标明使用推断语境的成功回答数，不能视为完整恢复了历史运行时语境。

## 验收

离线测试只能确认 `<br>` 修正、警告和指标逻辑，不能证明模型照做。改动效果需要真实模型对照，题目、合成资料、日历基准和 seed 都与[回答先表态与精简](回答先表态与精简.md)相同：

```powershell
& .\.venv\Scripts\python.exe scripts/compare_layers.py run --root . --label plain --mode single
& .\.venv\Scripts\python.exe scripts/compare_layers.py run --root . --label plain --mode multi
& .\.venv\Scripts\python.exe scripts/compare_layers.py report reports/compare/direct-single reports/compare/plain-single reports/compare/direct-multi reports/compare/plain-multi
```

旧版本结果不在本地时，按 `scripts/compare_layers.py` 开头的说明用 `git worktree` 检出上一版本重跑。指标表会重新统计旧结果的 `avg_jargon`、`avg_lead_jargon`。

预期：`avg_lead_jargon` 接近 0，`avg_jargon` 明显下降；`hedged_first`、`rejections` 不上升。仍需按报告里的人工检查逐题阅读。

## 风险

- 术语词表是固定的，漏掉的说法（如“伏吟”“羊刃”）不会产生警告，只能靠人工检查。
- 改成白话后判断可能写得更绝对；确定性说法禁令照常打回，对照表的 `rejections` 可以看到是否上升。
