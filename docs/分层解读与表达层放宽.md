# 分层解读与表达层放宽

## 背景

真实模型推演后，回复往往只有一句不超过 80 字的结论，后面跟一长串“依据”。原因有四个，它们互相叠加：

1. **输出结构**：`Reading` 里能写叙述的只有 `summary`（最多 80 字），没有正文字段。模型想多解释，只能写进 `evidence`。
2. **提示词**：提示词明确要求“summary 直接回答核心问题，余下要求在依据中回答”。
3. **渲染**：`render_reading` 把依据紧跟在结论之后，张力和共振不显示。
4. **校验**：措辞、句式、置信度等规则一旦违反就整份打回重交。每次重交都在教模型少写，只写有引用的句子。

## 原则：事实层严格，表达层放开

干支、柱位、落座、宫位、相位、日期、容许度、牌名与正逆位、ref_id，仍由代码逐项核对，写错照样打回。结构、语气和篇幅交给模型，代码能修的就直接修，不再打回。

## 输出结构

| 字段 | 变化 |
|---|---|
| `summary` | 80 → 200 字，用作定调，第一句直接回答问题 |
| `sections` | 新增，2–5 层分析（`title`、`body` ≤1200 字、`ref_ids`）。ref_id 挂在段落上，不再逐句绑定 |
| `closing` | 新增，收尾一句 |
| `evidence` | 保留，降级为附录：每条一句话写明引用的计算事实 |

渲染顺序（CLI 与网页聊天气泡共用 `render_reading`）：

定调 → 分层分析 → 行动建议 → 时间安排 → 彼此呼应 → 不同视角 → 收尾 → 依据条数 → 置信度 → 安全提示。

- 分层解读的回复只显示“解读依据：共 N 条计算事实”。命令行输入 `/evidence` 查看完整依据；网页解读面板把依据折叠在“查看解读依据”里。完整 evidence 仍保存在结构化记录中。
- 首次回复、追问回复和历史回看使用同一套渲染。
- 在此之前保存的记录没有 `sections`，仍按原来的版式显示（依据在前）。

多 Agent 模式下，专家报告新增 `analysis`（本体系推演，≤1500 字），`answer` 从 120 字放宽到 300 字。编排者把各体系的 analysis 融合成分层推演，审校看到的草稿也包含 sections。

## 校验分档

| 档位 | 内容 | 处理 |
|---|---|---|
| 硬性（打回） | 编造干支、柱位、落座、宫位、相位、日期、牌名或正逆位；evidence 或 sections 引用了本次以外的 ref_id；时辰未知时解读时柱、宫位或四轴；时间范围问题没有算行运或流期；隐瞒张力（多 Agent）；高风险问题缺少安全说明；危机情形；**“一定会/必然/注定”等确定性说法**；**劝阻就医** | 不变，检查范围扩大到 sections、closing 和专家 analysis。段落里的行运相位按本段 `ref_ids` 引用的事件核对相位、日期和容许度（见下文） |
| 自动修正 | 免责声明、内部状态词所在的句子 → 删除；“知识库” → “传统释义”；confidence → 有未审核释义时设为 low 并写明原因；systems_used → 按实际计算的体系填写；专家失败 → 在 confidence.reason 中写明缺少哪个体系及原因；提到身体部位或作息，而用户可见的正文里没有明确、肯定的就医建议 → 自动补“如有身体不适，请及时就医” | 修正后保存，不打回。只有整个字段都是免责声明或内部词时才打回 |
| 只记录 | 时机题、A/B 题第一句的句式；问到日主、起运日期、首步大运却没写出 | 写进 `submit_reading` 结果的 `warnings`，随 trace 保存 |

### 段落中的行运相位

一个段落可以引用多个事实，不要求每句都重复“行运”或完整事件名：

- 段落的 `ref_ids` 引用了行运事件时，段内的相位必须匹配其中一个事件，日期和容许度也必须是该事件的。段落没有引用的事件不能借用。
- 标题写了“行运……”时，正文续写的相位按行运核对。
- 不说“行运”、但与本命相位一致的句子，仍可以写在行运段落里。
- “这一相位的精确日期是……”这类只写日期的句子，按上一句匹配到的事件核对。写在相位之后、点明相位或精确日期的日期也一样（“木星拱太阳，精确日期是11月12日”）。
- 日期按分句归属：“木星拱太阳在11月5日精确，土星刑月亮在11月20日精确”中，两个日期各自核对本分句的相位。
- 专家的 `analysis` 按其 points 的 ref_id 做同样的检查。

## 已确认的取舍

1. **补五行 / 喜用神**：开放。程序不计算喜用神。解读可以根据月令与五行分布推断喜用倾向，并给传统的补益建议（颜色、方位、作息、饮食、随身物件），但须写明依据，用“倾向”表述。
2. **身体部位**：允许按五行与脏腑的传统对应谈养护，不作诊断。
   - 只有用户实际看得到的内容里有明确、肯定的求医建议（如“如有不适请及时就医”“建议去医院检查”）才算已经提醒。
   - “办公室在医院附近”这类无关提及、未展示的字段（追问建议、折叠的依据）都不算。缺少提醒时，代码在安全提示里补“如有身体不适，请及时就医，以医生的诊断为准。”
   - “无需就医”“不用去医院”等劝阻就医的说法直接打回，单 Agent、多 Agent 的最终回答和专家报告都检查。
3. **语气**：允许“倾向/容易/往往/大概率”，继续禁止“一定会/一定能/一定是/必然/必定/注定/肯定会/绝对会/百分之百/毫无疑问/铁定”。
   - 否定只有作用在确定性词本身时才算：直接否定（“不一定会”“并非注定”“不是必然”），或者同一分句中被否定的引导动词（“不代表事件必然发生”“并不意味着一定会”）。
   - 分句里出现无关的否定字不算，例如“不久后你一定会升职”“无论如何都一定会顺利”仍被拒绝。
   - “一定要保证睡眠”这类行动建议不受影响。
4. **范围**：单 Agent 与多 Agent 一起改。

解梦“不说预兆”、姓名“不作命运断言”属于各自体系的规则，保持不变。
