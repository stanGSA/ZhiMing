# 分层解读与表达层放宽

## 背景

真实模型推演后，回复往往只有一句不超过 80 字的结论，后面跟一长串“依据”。原因有四个，它们互相叠加：

1. **输出结构**：`Reading` 里能写叙述的只有 `summary`（最多 80 字），没有正文字段。模型想多解释，只能写进 `evidence`。
2. **提示词**：提示词明确要求“summary 直接回答核心问题，余下要求在依据中回答”。
3. **渲染**：`render_reading` 把依据紧跟在结论之后，张力和共振不显示。
4. **校验**：措辞、句式、置信度等规则一旦违反就整份打回重交。每次重交都在教模型少写，只写有引用的句子。

## 原则：事实层严格，表达层放开

干支、柱位、落座、宫位、相位、日期、容许度、牌名与正逆位、ref_id，仍由代码逐项核对，写错照样打回。结构、语气和篇幅交给模型，代码能修的就直接修，不再打回。

## 输出结构

| 字段 | 变化 |
|---|---|
| `summary` | 80 → 200 字，用作定调，第一句直接回答问题 |
| `sections` | 新增，2–5 层分析（`title`、`body` ≤1200 字、`ref_ids`）。ref_id 挂在段落上，不再逐句绑定 |
| `closing` | 新增，收尾一句 |
| `evidence` | 保留，降级为附录：每条一句话写明引用的计算事实 |

渲染顺序（CLI 与网页聊天气泡共用 `render_reading`）：

定调 → 分层分析 → 行动建议 → 时间安排 → 彼此呼应 → 不同视角 → 收尾 → 解读依据 → 置信度 → 安全提示。

在此之前保存的记录没有 `sections`，仍按原来的版式显示（依据在前）。网页解读面板同样按层显示，依据折叠在“查看解读依据”里。

多 Agent 模式下，专家报告新增 `analysis`（本体系推演，≤1500 字），`answer` 从 120 字放宽到 300 字。编排者把各体系的 analysis 融合成分层推演，审校看到的草稿也包含 sections。

## 校验分档

| 档位 | 内容 | 处理 |
|---|---|---|
| 硬性（打回） | 编造干支、柱位、落座、宫位、相位、日期、牌名或正逆位；evidence 或 sections 引用了本次以外的 ref_id；时辰未知时解读时柱、宫位或四轴；时间范围问题没有算行运或流期；隐瞒张力（多 Agent）；高风险问题缺少安全说明；危机情形；**“一定会/必然/注定”等确定性说法** | 不变，检查范围扩大到 sections 和 closing |
| 自动修正 | 免责声明、内部状态词所在的句子 → 删除；“知识库” → “传统释义”；confidence → 有未审核释义时设为 low 并写明原因；systems_used → 按实际计算的体系填写；专家失败 → 在 confidence.reason 中写明缺少哪个体系及原因；提到身体部位或作息 → 自动补“如有身体不适，请及时就医” | 修正后保存，不打回。只有整个字段都是免责声明或内部词时才打回 |
| 只记录 | 时机题、A/B 题第一句的句式；问到日主、起运日期、首步大运却没写出 | 写进 `submit_reading` 结果的 `warnings`，随 trace 保存 |

## 已确认的取舍

1. **补五行 / 喜用神**：开放。程序不计算喜用神。解读可以根据月令与五行分布推断喜用倾向，并给传统的补益建议（颜色、方位、作息、饮食、随身物件），但须写明依据，用“倾向”表述。
2. **身体部位**：允许按五行与脏腑的传统对应谈养护，不作诊断。正文没有提就医时，代码自动在安全提示里补上“如有身体不适，请及时就医，以医生的诊断为准。”
3. **语气**：允许“倾向/容易/往往/大概率”，继续禁止“一定会/一定能/一定是/必然/必定/注定/肯定会/绝对会/百分之百/毫无疑问/铁定”。同一分句里前面有否定词时不算，例如“不一定会”“并非注定”，以及知识库常用的“不代表事件必然发生”。“不管/无论……都一定会”仍算确定性说法。
4. **范围**：单 Agent 与多 Agent 一起改。

解梦“不说预兆”、姓名“不作命运断言”属于各自体系的规则，保持不变。

## 未包含

- 计划中可选的画像字段 `life_context`（职业、近况）没有加。目前通过提示词让模型使用用户在对话和画像中说过的处境，不编造个人事实。
- 尚未用真实模型重新跑 `scripts.live_test`。自动化测试全部离线，不能代表真实模型的篇幅与质量；上线前应按计划用固定问题对比新旧版本。
