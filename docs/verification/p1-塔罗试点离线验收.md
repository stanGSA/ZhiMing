# P1 塔罗试点：实现与离线验收

根因整改计划（[根因整改实施计划.md](../根因整改实施计划.md)）的 P1。基线 `claude_modify_model@cadf72b`，日期 2026-10-31。全部离线，未调用付费模型；真实模型评测由负责人在本机执行（见文末）。

## 怎么用

`config.yaml` 中 `mode: pipeline` 时，塔罗问题走新流水线，其余问题仍走原来的 agent 循环。默认仍是 `mode: single`，流水线只在显式开启时生效。

- `pipeline.systems: [tarot]`：本阶段只开放塔罗。
- 命令行：`cli.py chat --mode pipeline`。
- 离线演示模型（`--provider demo`）只会回放工具调用、不能撰写，所以在 pipeline 模式下也继续走 agent 循环。

## 一次塔罗提问的流程

| 阶段 | 由谁完成 | 实现 |
| --- | --- | --- |
| ① 意图 | 代码 | `pipeline/intent.py`：塔罗页，或只问塔罗的消息 → 新解读；"第二张牌什么意思""不要重新抽" → 追问最近一次塔罗解读；"请重新抽一次" → 新解读；"继续" → 接着上次没写完的抽牌。其余返回 None，交回 agent 循环。塔罗不需要模型判断意图。 |
| ② 资料检查 | — | 塔罗不需要出生资料。 |
| ③ 计算 | 代码 | `start_reading`、`draw_tarot` 作为计划调用，经 `execute_calls` 执行：Guard、缓存、独占（每条记录只抽一次）、trace 与模型调用完全一致。用户选牌、页面所选牌阵照常生效。 |
| ④ 事实表 | 代码 | `pipeline/factsheet.py`：每张牌一行，含编号、牌位、【牌名】方向、关键词、一般含义。模型只看得到 R 编号，看不到完整引用。 |
| ⑤ 撰写 | 模型（1 次，不带工具） | `pipeline/compose.py`：普通文本加标记（【表态】【摘要】【分层】【引用】【建议】【收尾】），提到牌只写 `{{R2}}`。 |
| ⑥ 渲染与校验 | 代码 | `pipeline/render.py` 把占位符换成"【正义】逆位"，生成 `submit_reading` 的参数；`question_type`、`systems_used`、`evidence`、置信度、安全提示都由代码填写。`pipeline/verify.py` 检查牌位与牌是否对应、是否写了没抽到的牌。最后以计划调用的方式交给 `submit_reading`：`validate_reading`、存储、追问回复的保存都照旧。 |
| ⑦ 修复 | 模型（最多 1 次） | 一次列出全部问题（格式、未知编号、牌位不符、校验报错），并给出可引用的编号。 |
| ⑧ 降级 | 代码 | 仍不过时，由代码按牌面关键词写一份基础解读并照常提交，标记 `degraded`。 |

**调用上限。** 每条用户消息最多 2 次模型调用（撰写加一次修复），不再有"步数上限"。整轮仍受 `limits.request_timeout_s` 约束。

**中断后继续。**

- 抽牌完成后，读解状态的快照存进 `pipeline_runs`（库版本 6）。
- 模型出错、超时或进程重启后，用户发"继续"，就用同一副牌接着写，不会重抽。
- 保存或放弃后，这一行即删除。
- 清除记录、注销账户会一并删除；游客登录并入账户时随记录一起迁移；导出文件会列出未完成的抽牌。

## 与计划的出入

- **塔罗的意图判断全由代码完成**，不调用模型。按计划"代码优先、代码判断不了才问模型"，塔罗用不到模型，所以每轮最多 2 次调用，而不是 3 次。
- **提交沿用现有的 `submit_reading`**，没有另写存储路径。流水线产出的解读与 agent 循环的格式完全相同，网页、历史记录、导出都不用改。
- **`pipeline_runs` 只保存未完成的流程。** 完成后即删除，库里不会多一份已保存解读的副本。
- **网页没有新增"继续"按钮。** 中断时的提示语会请用户发送"继续"。

## 还需要真实模型验证的事（负责人在本机执行）

脚本模型只能证明流程与事实保证，不能证明真实回答的质量。按计划 P1 的退出标准：

```powershell
# 调参集：当前 single 与 pipeline 同批次对照（各 3 次重复、rubric v2、pro 评委）
.venv\Scripts\python.exe -X utf8 -m scripts.live_week23 --dataset evals/cases/tarot_pilot.yaml --judge pro --repeats 3 --mode single
.venv\Scripts\python.exe -X utf8 -m scripts.live_week23 --dataset evals/cases/tarot_pilot.yaml --judge pro --repeats 3 --mode pipeline
# 留出集（脚本断言、调用次数、耗时参考）
.venv\Scripts\python.exe -X utf8 -m scripts.live_test --mode pipeline
# P1 结束时：最终验收集，两种模式各跑一次，期间不据此调整
.venv\Scripts\python.exe -X utf8 -m scripts.live_week23 --dataset evals/cases/tarot_final.yaml --judge pro --repeats 3 --mode single
.venv\Scripts\python.exe -X utf8 -m scripts.live_week23 --dataset evals/cases/tarot_final.yaml --judge pro --repeats 3 --mode pipeline
```

**要看的数字：**

- 提交率、脚本断言通过率
- 已提交回答的质量通过率
- 任务完成且无工具错误
- 每轮模型调用（应 ≤ 2）
- 修复率、降级率
- P50/P95 耗时、每题输入 token

通过条件以最终验收集为准，见计划 P1。

## 已知限制

- **追问只指向最近一次塔罗解读**（或网页历史中选定的那一条），不支持"三天前那次"这类说法。
- **"问道"页只有消息明确只问塔罗时才走流水线。** 涉及其他体系的问题仍走 agent 循环，留到 P3。
- **`question_type` 由关键词判断。** 二选一牌阵记为 decision，含"下个月""什么时候"等记为 timing，其余记为 tarot。
- **降级解读只有牌面的一般含义**，不结合问题。它只在两稿都未通过时使用，并在结果中标记 `degraded`。
