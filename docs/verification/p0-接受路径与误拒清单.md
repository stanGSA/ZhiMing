# P0.2 接受路径与误拒清单

根因整改计划（[根因整改实施计划.md](../根因整改实施计划.md)）的 P0.2。日期 2026-10-30，基线 `main@506574c`。全部离线，不调用模型。

## 方法

**1. 生成正确陈述，检查是否被拒（`tests/validation/test_accept_paths_generated.py`）**

用真实计算结果为六个体系生成"正确答案可能的写法"，逐句交给 `validate_reading`，断言全部通过。句子由计算结果拼出，不手写干支或牌名，计算器或校验器改动后会自动跟着变。

| 体系 | 场景 | 句数 |
| --- | --- | ---: |
| 八字 | 原局、流月 | 30 余 |
| 占星 | 本命、行运 | 约 100 |
| 塔罗 | 三张牌 | 6 |
| 每日运势 | — | 约 10 |
| 姓名五格 | — | 4 |
| 解梦 | — | 2 |

另外加了两类：混合本命与行运的段落、否定错误值的句子。

**2. 改错一个事实（变异），检查是否被拒**

每个体系把一个事实改错，断言被拒。当前放过的错误标为严格 xfail（strict）：修好后测试会转为失败，提醒去掉标记。

**3. 正确的工具调用能否通过 Guard（`tests/runtime/test_reference_call_sequences.py`）**

对 P1 主集里需要计算的 12 道题，按正确顺序调用工具（解析地点、排盘、算流期、抽牌），看 Guard 是否放行。用来判断 P1 中 122 次"C 类"来源错误是 Guard 过严，还是模型调用有误。

## 结果一：误拒（正确的话被拒），已在 P0.3 修复

| # | 体系 | 被拒的正确写法 | 原因 | 位置 |
| --- | --- | --- | --- | --- |
| 1 | 塔罗 | 这次抽到的是正义逆位，**不是正义正位**。 | 否定另一方向的说法被当成本次牌面断言 | `plugins/tarot/validation.py::orientation_error` |
| 2 | 塔罗 | 正义正位一般表示阻滞，**这次不是这种情况**。 | 一般牌义句后面的逗号分句出现"这次"，整句被当成本次断言 | 同上，`DRAW_CONTEXT` 按整句匹配 |
| 3 | 占星 | 太阳**不在**白羊座；你的太阳**不在**处女座，而在狮子座；太阳**不在**第10宫，而在第4宫。 | 落座只取行星后面第一个星座、宫位取后面所有宫位，都忽略前面的否定 | `plugins/astro/validation.py::validate_output` 的落座与宫位检查 |

P0.3 的修复只改校验器，不动提示词：

- `common/facts.py` 新增 `negated_at`：紧跟在"不是、并非、不在、没有落在"等否定词后面的值，视为被否定的值，不算断言。只看紧邻的几个字，不会让句中任意一个"不"字抵消断言。
- 塔罗：被否定的另一方向不再报错；"这次不是/并非……"不再被当作本次断言的语境；"本次正义是逆位"也算已写明正确方向。
- 占星：落座取第一个未被否定的星座，宫位只取未被否定的宫位。
- 同时加了反向变异，保证修复没有放松：否定正确方向、却断言错误方向的句子仍被拒；"一般表示……，这次抽到的正是它"仍被拒；"不在狮子座，而在白羊座"（实为狮子）仍被拒。

## 结果二：按设计拒绝，不改

| 写法 | 说明 |
| --- | --- |
| 行运日期写 UTC 日期，而当地日期不同（如北京时间次日凌晨的事件写成前一天） | 设计如此：日期按咨询时区表述（`common/domain_rules.py`） |
| 用未抽出的牌作对比，如"不像死神牌那样" | 设计如此：正文只能出现本次抽出的牌。流水线中由闭集比对统一处理 |

## 结果三：漏拦（错误事实被放过），留给流水线闭集比对

这些在旧校验器里补规则，只会继续加长正则；按计划在 P1～P3 的渲染层（占位符加闭集比对）中解决。测试里已用严格 xfail 记录。

| 体系 | 被放过的错误写法 |
| --- | --- |
| 八字 | 日主写错（辛金写成庚金等） |
| 八字 | 原局十神写错（"月柱庚申为比肩"，实为劫财） |
| 八字 | 首步大运写成后面某一步大运的干支 |
| 八字 | 流月与原局的关系类型写错（冲写成合） |
| 占星 | 行运日期写错，但日期与相位之间隔了一个逗号（"2月9日前后，行运木星……"）；不隔逗号时能拦住 |
| 塔罗 | 牌位张冠李戴（过去位、未来位的牌对调） |
| 塔罗 | 未抽出的大阿卡纳不带书名号或"牌"字（"现在位抽到了恋人"） |
| 每日运势 | 流日十神写错 |

## 结果四：Guard 不是 C 类错误的来源

| 题目 | 正确调用序列 |
| --- | --- |
| `astro_trait`、`bazi_trait`、`bazi_timing`、`three_system_timing`、`unknown_time`、`investment_new`、`natural_astro`、`natural_bazi`、`range_before_birth`、`overseas_bazi`、`natural_unknown` | 全部通过 Guard |
| `astro_timing` | 排盘通过；`compute_transits` 返回 `needs_input: confirm_period_timezone`，要求确认日期区间按哪个城市的时间 |

**结论**

- P1 中 C 类错误（画像写入越界 74 次、资料未确认就计算 48 次）来自模型的调用方式（缺陷 D3），而不是 Guard 比规则更严。流水线由代码按上面的序列调用后，这两类错误会从结构上消失。
- `astro_timing` 是规则与评测期望不一致（缺陷 D2）的实例：评测期望直接作答，代码按 `9a626a5` 的设计先问时区（出生地不等于现居地）。这条留给 P3 的资料需求表决定，需要负责人拍板：海外出生且未说明现居地时，是先追问，还是默认用出生地时区并在回答中注明。

## 数字

- 生成的正确陈述：约 150 句。误拒 3 类，全部在塔罗和占星。
- 变异：24 个错误事实里，16 个被拦住，8 个被放过（漏拦）。
- 八字和占星的正面写法（干支、十神、流月关系、落座、宫位、本命相位、行运日期）没有发现误拒。P1 里八字表现最差，主要原因不在校验器，而在流程（见结果四和 [按体系基线](p1/baseline-by-system.md)）。
