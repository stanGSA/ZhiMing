# P0.2 接受路径与误拒清单

根因整改计划（[根因整改实施计划.md](../根因整改实施计划.md)）的 P0.2。日期 2026-10-30，基线 `main@506574c`。全部离线，不调用模型。按 PR #34 评审意见修订。

## 方法

**1. 生成正确陈述，检查是否被拒（`tests/validation/test_accept_paths_generated.py`）**

用真实计算结果生成"正确答案可能的写法"，逐句交给完整的 `validate_reading`，断言全部通过。句子由计算结果拼出，不手写干支或牌名，计算器或校验器改动后会自动跟着变。共 323 句。

| 体系 | 场景 | 问题类型 |
| --- | --- | --- |
| 八字 | 原局、大运（男，时辰已知）；原局（时辰未知、无性别）；流月（一个区间） | timing、trait |
| 占星 | 本命含宫位（时辰已知）；本命不含宫位（时辰未知）；行运（一个区间） | timing、trait |
| 塔罗 | 三张牌、单张、二选一 | tarot |
| 每日运势 | 一个日期 | daily |
| 姓名五格 | 一个复姓名字 | name |
| 解梦 | 两个命中意象 | dream |

另外还有两类：本命与行运混在同一段落，以及否定错误值的句子。

**2. 改错事实（变异），检查是否被拒**

共 35 个变异。当前放过的标为严格 xfail（strict）：修好后测试会转为失败，提醒去掉标记。

**3. 正确的计算调用能否通过 Guard（`tests/runtime/test_reference_call_sequences.py`）**

对 P1 主集里需要计算的 12 道题，在当前代码上按正确顺序调用计算工具（解析地点、排盘、算流期、抽牌），看 Guard 是否放行。不含 `submit_reading`。

## 结果一：误拒（正确的话被拒），已在 P0.3 修复

| # | 体系 | 被拒的正确写法 | 原因 |
| --- | --- | --- | --- |
| 1 | 塔罗 | 这次抽到的是正义逆位，**不是正义正位**。 | 否定另一方向的说法被当成本次牌面断言 |
| 2 | 塔罗 | 本次正义是逆位。正义正位一般表示阻滞，**这次不是这种情况**。 | 一般牌义句后面的逗号分句出现"这次"，整句被当成本次断言；"正义是逆位"也没被认作写明了正确方向 |
| 3 | 占星 | 太阳**不在**白羊座；你的太阳**不在**处女座，而在狮子座；太阳**不在**第10宫，而在第4宫。 | 落座、宫位检查忽略了前面的否定 |

**修复规则。** 只改校验器，不动提示词。

- `common/facts.py::value_claim` 区分断言、否定与否定推论：前缀判断直接否定（"不是、并非、不在、没有落在"等），完整值后紧接的句法区分"并非狮子座就一定外向"或"并不是狮子座的人都外向"。后两者否定的是推论，不是落座；不作为事实断言，也不作为塔罗已写明正确方向的锚点。"并非不在白羊座"这类双重否定仍按断言处理。
- 被否定的值仍是可核验的陈述，不会被跳过：
  - 断言的值必须等于计算值；
  - 被否定的值必须不等于计算值；
  - 否定计算值和断言错误值一样会被拒。
- 塔罗：只有收尾的分句明确否认"这个一般牌义适用于本次"（如"，这次不是这种情况"），才解除本次语境。不再从句中任意位置删去"这次不是"等词。
- 占星：落座仍只以第一个被断言的星座为该行星的星座，与修复前一致。

**评审指出的回归（第一版修复跳过了所有否定值），已修复并加入测试：**

| 写法（实际：太阳狮子座第4宫；第二张为正义逆位） | 第一版修复 | 现在 |
| --- | --- | --- |
| 太阳不在白羊座，也不在狮子座。 | 放过 | 拒绝 |
| 太阳不在第4宫，也不在第5宫。 | 放过 | 拒绝 |
| 太阳并非不在白羊座。 | 放过 | 拒绝 |
| 正义逆位。正义正位代表这次不是偶然的阻滞。 | 放过 | 拒绝 |
| 正义逆位。正义正位表示这次不同于上次的僵持。 | 放过 | 拒绝 |
| 这次不是正义逆位。 | 放过（修复前也放过） | 拒绝 |

**合并 PR #34 后补充的误拒修复：** 不能把否定推论误当成否定真实值。真实太阳狮子座时，"太阳狮子座，并不是狮子座的人都外向"、"太阳狮子座，但并非狮子座就一定外向"应通过；真实正义逆位时，"本次抽到正义逆位。并不是正义逆位就意味着无法推进"也应通过。接受路径生成器新增 7 句正例和 7 个事实冲突变异；其他公开字段及正逆位由插件回归测试补充覆盖。推论句不覆盖同段落中独立的错误落座／方向，也不能替代塔罗一般牌义对照所需的正确方向锚点。原 323 句与 35 个变异的统计为 P0 初次样本。

## 结果三：漏拦（错误事实被放过），留给流水线闭集比对

在旧校验器里补规则只会继续加长正则，按计划在 P1～P3 的渲染层（占位符加闭集比对）中解决。测试里以严格 xfail 记录。

**关闭条件：** 对应体系进入流水线后，这些用例要在流水线的校验路径上转为通过，再删除 xfail 标记。只让旧校验器继续运行，不算解决。

| 体系 | 被放过的错误写法 | 关闭阶段 |

## 结果四：当前代码上存在能通过 Guard 的计算路径

| 题目 | 正确计算调用序列（当前代码） |
| --- | --- |
| `astro_trait`、`bazi_trait`、`bazi_timing`、`three_system_timing`、`unknown_time`、`investment_new`、`natural_astro`、`natural_bazi`、`range_before_birth`、`overseas_bazi`、`natural_unknown` | 全部通过 Guard |
| `astro_timing` | 排盘通过；`compute_transits` 返回 `needs_input: confirm_period_timezone`，要求确认日期区间按哪个城市的时间 |

**能说明的：**

- 在当前代码、所测输入下，P1 这些题存在合法的计算路径，Guard 不会挡住正确的计算调用。
- 这支持"C 类错误主要来自模型选错调用（缺陷 D3）"的判断。流水线由代码按这些序列调用，就不再依赖模型选对调用。

**不能说明的：**

- 不能据此断言历史上 122 次 C 类错误全部由模型造成：归档批次跑的是更早的未提交源码（见计划附录 A），本实验没有运行那份源码。
- 不能据此证明整条解读的提交路径不会误拒：序列不含 `submit_reading`。提交路径的误拒由上面的接受路径测试另行检查，覆盖范围见前文。

**`astro_timing`** 是规则与评测期望不一致（缺陷 D2）的实例：评测期望直接作答，代码按 `9a626a5` 的设计先问时区（出生地不等于现居地）。留给 P3 的资料需求表决定，需要负责人拍板：海外出生且未说明现居地时，是先追问，还是默认用出生地时区并在回答中注明。

## 数字

- 生成的正确陈述 323 句：误拒 3 类，都在塔罗和占星，已修复。
- 变异 35 个：拦住 27 个，放过 8 个（漏拦）。
- 在所测样本上，八字和占星的正面写法（干支、十神、流月关系、落座、宫位、本命相位、行运日期）没有发现误拒。
