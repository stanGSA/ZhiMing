# r9 校验复核

本轮保持产品代码与提示词固定，以下均为离线回放，0 次模型调用；不修改原始评分。

## 1. 普通中文跨词边界被识别为干支

`Dream-single / dream_hospital_health#2` 三次提交均被拒为“本次工具结果没有该干支，不能编造”，随后达到重复失败上限。三份实际拒绝稿均可重现该错误，命中来自“给自己申请……”中的“己申”，并非八字断言。实际原句包括“梦里病倒，有时反而是心里在给自己申请一个可以停下来的理由”。

| 最小文本 | 当前八字输出校验 |
| --- | --- |
| 像是在给自己申请一个休息的理由。 | 误拒，匹配“己申” |
| 先安排一段休息。 | 放行 |
| 你的日柱是甲子。 | 无相应计算事实，仍拒 |

根因位于 `plugins/bazi/validation.py::validate_output`：对全部公开文本匹配任意天干字加地支字，再与计算事实比较，未识别普通词语边界或八字断言语境。该校验也会作用于解梦回答。本轮仅定位，不据此宣称是 PR #51 新引入。证据见 [bazi-false-positive-replay.json](bazi-false-positive-replay.json)。

## 2. 命中来源短语的归属冲突

`Dream-pipeline / dream_late_grandmother#1` 的实际事实表将来源短语“去世的奶奶”以查询“奶奶”命中“祖父母”，另有“房子”和“做饭”。原稿复述“你梦到去世的奶奶在老房子里给你做饭”，被拒为“去世的亲人不是本次命中的意象”。修复一次后提交，最终四维评分通过，无降级。

| 以该题实际事实表作最小回放 | 当前解梦校验 |
| --- | --- |
| 你梦到去世的奶奶在老房子里给你做饭。 | 拒绝，归为未命中的“去世的亲人” |
| 你梦到奶奶在老房子里给你做饭。 | 放行 |
| 去世的亲人象征新的财富。 | 仍拒，不能据复述问题放开新释义 |

第一句没有新增梦境内容或释义，却与本题已接受的来源短语冲突。输入抽取允许该短语命中“祖父母”，输出 `ungrounded` 使用词典更长别名归为“去世的亲人”；现有 `phrase_aliases` 只绑定后缀别名，`phrase_hits` 只绑定受控归一化，未解决这种归属冲突。证据见 [dream-validation-replay.json](dream-validation-replay.json)。不扩大“去世的亲人”的可解读范围，不通过改写本轮原稿掩盖问题。

## 3. 其他解梦拒绝稿与既有守卫

Dream-pipeline 全部 4 份拒绝稿均已用实际命中及本轮知识库重现。除上述奶奶复述外，`dream_chased_to_exam#1` 解读未收录考场及“跑进考场才发现没复习”；`dream_chased_to_exam#2` 从“没复习”作额外推断；`dream_flood_and_snake#2` 从“不敢下去”状态作推断。这三次修复符合当前闭集约定，不自动当作程序缺陷。

r8 的“梦里牙齿是一颗一颗掉下来的”及不带“是”的原句均放行，“梦里牙齿象征财富”仍拒。r7 医疗正反疑问与明确否定“稳赚”的指定原句也通过，劝阻就医和肯定“稳赚”的对照仍拒。这些为离线原句回放，不冒充本轮模型恰好写出相同变体。

## 4. “三者”被误读为地格数值 3

`Name-single / name_compound_surname#1` 的三份实际拒绝稿均被拒为“欧阳子涵的地格3与本次计算不符”，随后达到重复失败上限。实际计算地格为 15，稿件的五格数值也写了地格15；错误命中来自“三才指天格、人格、地格三者尾数对应的五行”。

| 用该题实际计算事实作最小回放 | 当前姓名校验 |
| --- | --- |
| 三才指天格、人格、地格三者尾数对应的五行。 | 误拒，将“地格三”视为数值断言 |
| 三才由天格、人格及地格的尾数推得。 | 放行 |
| 欧阳子涵的地格15。 | 放行 |
| 欧阳子涵的地格3。 | 仍拒，保留错误数值守卫 |

根因位于 `plugins/name/validation.py::CLAIMED/GRID`：数值与名词边界排除了部分量词和“三才”等完整词，但没有排除“三者”。这不代表三份完整稿件没有其他叙述或质量问题，只说明已记录的首个错误可缩小到一句没有错误数值的普通说明。证据见 [name-false-positive-replay.json](name-false-positive-replay.json)。本轮不改产品源码。

`name_career_grid#2` 三份提交同样把“地格三者”读成地格3；林晓实际地格17。以该题实际数据回放均已重现，见 [extra-name-single-review.json](extra-name-single-review.json)。

## 5. 明确集体指代插入冒号后失去归属

`Name-pipeline / name_compare_two#3` 初稿与修复稿都报“有多个姓名时，外格2须写明是哪个名字”，最终 keywords 降级，质量因未比较“哪个更好”失败。两份拒绝稿均已按本题实际事实表展开并重现。建议项写“两个名字：都留意外格2数提示的基础与分工问题”；本题只有张伟、李娜，两者外格都为 2。

| 本题实际姓名事实下的最小回放 | 当前姓名校验 |
| --- | --- |
| 两个名字：都留意外格2数提示的基础与分工问题。 | 拒绝，无归属 |
| 两个名字都留意外格2数提示的基础与分工问题。 | 放行 |
| 张伟的外格2、李娜的外格2。 | 放行 |
| 两个名字都留意外格3。 | 仍拒，张伟的外格值错误 |

`COLLECTIVE` 要求“两个名字”直接接“都”，未覆盖常见建议标签中的冒号；明确指向两者且数值相同的语句因此被当作无归属。不能把这两份完整稿件所有文字都判成正确，但最小对照说明首个报错存在语法范围遗漏。此前批准的集体指代检查仍有效，后续修复应保持逐人核对数值；本轮只记录。证据见 [name-collective-replay.json](name-collective-replay.json)。

## 6. 算式结果错误归属于最后一个操作数

`Name-single / name_without_lead_in#3` 写“外格由天格加地格减人格得18”。真实天格17、地格26、人格25、外格18，17+26−25=18正确。正则把末尾“人格得18”当作独立人格断言，报人格18与计算不符。前两稿先被重复免责声明拦截，后3稿由此触发重复失败上限。

| 使用该题实际计算的最小句 | 当前姓名校验 |
| --- | --- |
| 外格由天格加地格减人格得18。 | 误拒，将18归属于人格 |
| 外格等于天格加地格再减去人格，计算结果为18。 | 放行 |
| 陈思远的外格18。 | 放行 |
| 陈思远的人格18。 | 仍拒，保留错误人格守卫 |

这是 `GRID` 的另一类局部数值解析缺陷，应单列第五类，见 [extra-name-single-review.json](extra-name-single-review.json)。该回放仅针对姓名谓词，不覆盖完整提交事务或其他层的免责声明检查。
