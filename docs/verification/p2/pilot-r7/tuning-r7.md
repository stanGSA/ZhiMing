## 2. 预兆：只认管得着它的否定

`35233fe` 的判断是：预兆类词前 6 个字里有“不、非、没有、无、并未、别”中的任何一个，就算否定。这样会误拒，也会放过：

- **误拒：** “比担心预兆更有用”。前 6 个字没有否定字，但“担心预兆”是被劝放下的对象。
- **放过：**
  - “这不是坏事，它预示着……”“不是坏事而是预示……”：先否定后肯定；
  - “不幸的预兆”“这种不安预示”“无疑预示”“非常明确地预示”“别人……预示”“不久会发生”：词里带着否定字，本身并不否定。

**r7 的判断（`prophecy_negated`）：**

1. 先用共用的 `output_policy.negates_claim`（确定性用语已在用）判断小句里的否定是否管到这个词。它只认直接否定（“不预示”“不一定会”）和否定框架（“不代表……”“并不意味着……”），遇到转折就重新开始。
2. 预兆、征兆、兆头、预言作名词时，另外接受否认或劝放下它的说法（`DENIED_OMEN`）：
   - 否认：不是健康的预兆、没有什么预兆、不作为现实预兆；
   - 劝放下：别把梦当成预兆、不必担心预兆；
   - 比较：比担心预兆更……、与其担心这是不是预兆……（r6 的两种写法）。

   中间最多夹一个两字修饰词，但不能是“一般、普通”（“不是一般的预兆”意思正相反）。转折（而是、但、却……）之后重新判断。

**回归：** 对词典全部解梦条目，以及历次发布证据里含预兆类词的 164 个句子，比较新旧判断，结果：

- 词典条目里没有新拒；
- 原来被误拒的“不代表现实事件的预兆”（词典原文，降级时会用）改为放行；
- 新拒的只有文档里本来就是反例或说明的句子（如“它预示你很快会在工作上得到认可”）。

## 3. 奔跑：被追时自己的跑

用户说“被人追着一直跑”。这里的跑就是被追的一部分，词典“被追”的关键词里也有“逃跑”。所以“梦里的奔跑”说的是命中的“被追”，不是另一个意象“跑步”。

**条件（`chase_aliases`），全部满足才绑定：**

- 命中了“被追”，没有命中“跑步”；
- 用户原话同一小句里有“被……追（着/得）+ 至多一个副词（一直、拼命、不停地……）+ 跑/奔跑”；
- 只在流水线里生效：单 agent 校验器没有 `pipeline_run` 标记，不继承。

**只绑定词典别名“奔跑”：**

- “跑步”本身从不绑定；
- “你梦里一直跑，这个画面说明……”这类复述仍按事实表外内容拒（现有测试保留）。

## 4. 姓名：“两个名字都……”

张伟、李娜的外格都是 2。“两个名字都可留意外格2”同时说两人，说的是对的。

**规则（`COLLECTIVE`）：**

- 写法：“（这）两/二/三……个名字/个姓名/位/人 +（的……）+ 都/均/皆”；
- 数目必须等于本次姓名数，且至少两个；
- 前面紧接“非、不是、未必、不”时不算；
- 只管同一句里写在它后面的数值，每个名字都要对得上；
- 它后面再写出一个全名，后面的数值归这个名字。

单字笔画（STROKE）在多名字时本来就对照所有名字，行为不变。

## 5. 稳赚：只改提示词

`HIGH_RISK_CLAIM` 的注释写明 “negated or not as written here”，`policy_judge.HARD` 也一样：“稳赚”等词否定也拒，并计入两稿安全降级。这是共用安全规则的语义，改不改由负责人决定（见 [复核 §6](../pilot-r6/review.md)）。

r7 只做提示词这一侧的修复：撰写提示里写明这几个词在否定或提醒里也不要写，改说“不保证收益”“有亏损的可能”。r6 的问题是模型不知道规则比提示更严，这一点可以定位到提示词。
