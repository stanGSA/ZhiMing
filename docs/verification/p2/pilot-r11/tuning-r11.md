## 1. 修复请求引出触发原句（通用）

**改动：**解梦、姓名、每日运势流水线在修复前，把草稿按句拆开，每句单独用同一套检查重跑一遍：

- 本体系的闭集检查（`system.problems`）；
- 高风险问题上提交时的确定性/稳赚规则。

单独一句就能报出与原问题**完全相同**文本的，就是触发句。修复请求在这条问题下面写出：

```
1. 不能给出健康、投资或生死的确定性结论
   出问题的句子：“这笔投资稳赚。”
   请换一种说法重写这些句子，不要沿用原来的措辞。
```

**边界：**

- 每个问题最多引两句；
- 格式问题，以及找不到触发句的问题，照旧只列出问题描述；
- 检查规则本身一条没改，只是把已经判定的结果说得更具体；
- 引出的句子写入 trace，即 `pipeline_stage` 中 `repair` 的 `quotes` 字段，可以对照模型改了没有；
- 塔罗不用这个改动，保持它通过 P1 最终验收时的修复请求。

**预期：**规则误判时，模型会换一种说法，一次修复就能通过，不再两稿后降级。按现行口径，这类误拒就不再阻断。新的说法同样要过全部规则，所以不放宽任何守卫。
