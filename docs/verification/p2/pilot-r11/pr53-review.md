## 1. 可操作问题

### F1 / P2：解梦新增否定规则未正确处理外层否定

位置：`plugins/dream/validation.py:258–270`，重点是 `NO_PROPHECY` 及两个直接返回 True 的分支。

`NO_PROPHECY` 只排除紧邻的“不是”“并非”“不能说”。对于“不可能没有预示”“不能说这个梦没有预示”等表达，外层否定没有被识别，末尾“没有”仍被当作否定预兆。`DECLINED` 同样未检查自己的否定是否被外层否定，例如“不是不提供预言”。

完整 Dream pipeline 对照：

| 草稿原句 | PR 当前校验 | 换回基线对应校验 |
| --- | --- | --- |
| 这个梦不可能没有预示现实中的好转。 | 原句提交，0 修复 | 拒绝原句，修复 1 次后提交 |
| 不能说这个梦没有预示现实中的好转。 | 原句提交，0 修复 | 拒绝原句，修复 1 次后提交 |
| 这个梦不是不提供预言。 | 原句提交，0 修复 | 拒绝原句，修复 1 次后提交 |

这些是肯定或保留预兆含义的表达，不能按无预兆免责声明处理。实际产物中保留了这些句子，说明问题同时穿过了 pipeline 检查和最终提交。

建议：在识别到内层否定后检查完整作用范围及外层否定；可结合现有 `governing_denial` / `denial_negated` 的方式，补足“不可能”等表达。对 `DECLINED` 也应用同类检查，而不是再增加几个固定负向回顾。

### F2 / P2：上升星座豁免以单字判断，放过真实四轴解读

位置：`plugins/astro/validation.py:145`。

新增字符集包含“性”，会无条件豁免“阳性上升”“阴性上升”。这些是上升星座属性的占星说法，并不表示某个数量正在增加。由于这类句子不写具体星座或宫位，后面的落座/宫位检查也不会拦截。

完整 Daily pipeline 中将出生时间设为未知（计算结果 `natal.time_known=false`）：

- “你是阳性上升，外在表达主动。”直接提交，0 修复。
- “你的阴性上升让你显得内敛。”直接提交，0 修复。
- 同一运行环境换回基线 Astro 校验后，两句都因出生时间未知被拒，修复 1 次后提交。

建议：把普通“上升”动词限定到完整数量词语或受控结构，并优先识别明确的占星术语。不能仅凭前一个字就跳过整个未知时辰守卫。

### F3 / P2：姓名量词“点”的通用豁免吞掉中文小数错值

位置：`plugins/name/validation.py:27`。

作者为“一点”添加的“点”位于通用中文数字后的负向检查中，因此所有以“点”继续的中文数值都不再匹配。例如“二十四点五”被整段跳过。

完整 Name pipeline 对照：

- “陈思远的人格二十四点五。”在 PR 中直接提交，0 修复。
- “陈思远的数理二十四点五。”也直接提交，0 修复。
- 换回基线数值正则后，均识别到不符的数值 24，要求修复，原句未进入提交产物。

五格不应接受这些小数陈述。“一点”作为日常程度用语的豁免不能覆盖全部中文数字加“点”的结构。

建议：对“一点”“一些”按完整词及后续上下文处理；显式识别并拒绝不合法的小数五格，或确保其仍进入数值校验。

### F4 / P2：评委尾逗号修补会修改 JSON 字符串中的证据

位置：`scripts/live_week23.py:90–97`。

`TRAILING_COMMA.sub` 对整段文本执行，不区分 JSON 结构、字符串和转义状态。只要回复存在需要修补的结构尾逗号，字符串内容中的逗号也会一起被删除。

复现：有效四维布尔字段，`reasons` 为 `["引用的原文包含 ,} 和 ,]。"]`，对象末尾带一个真正尾逗号。调用 `judge_answer` 后：

```json
{
  "reasons": ["引用的原文包含 } 和 ]。"],
  "json_trailing_commas_removed": true
}
```

四维布尔值在该样本中没有变化，但评分理由中的原文被改写。成功修补路径的 `quality_review` 也没有保存原始回复，因此仅凭结果行无法还原被删除的内容。

建议：按字符扫描并维护字符串/转义状态，只删除字符串外、闭合括号前的结构逗号；为成功修补保留原始回复或可核对的修补记录。
