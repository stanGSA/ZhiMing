# 八字原局／流期校验与失败恢复修复

日期：2026-10-28

## 原因

自动生成的流期证据 `period:…:year:…` 曾被翻译为 `period:…:年柱:…`，随后原局柱位正则将流年年柱与出生年柱比较。相同证据不随正文改写而变化，导致重复拒绝。提交失败后的 `read_reading` 只查已保存记录，读取不到当前草稿；重新开始则会清除已有计算并继续耗费步骤。

## 修改

- 流期事实明确渲染为流年、节气流月、流日、流时，与原局作用对象分开标注。
- 原局按出生盘核对，流期按对应年／月／日／时计算集合核对；兼容旧版证据格式。按字段、句子和已识别柱位划分语境，错误包含字段位置和正确值。
- 提交错误返回修正指引，保留完整草稿及规范引用；上下文压缩和读取未提交记录均能恢复草稿，同轮失败后禁止用新记录清除已有计算。
- 相同工具、错误码和错误信息在一轮内累计三次失败时返回 `validation_stalled`；未通过校验的内容不会保存或发布，下一轮可以继续修正。原有预算和12步上限保持不变。

## 验证

- 用原始失败日志离线回放五次提交：旧校验均拒绝，新校验在旧版和新版证据渲染下均通过。
- 445项回归测试通过，覆盖 harness、validation、八字集成、专家状态恢复、多 Agent 重试与期限以及 runtime。
- 最新专项测试27项通过：`tests/validation/test_bazi_scopes.py`（21项）与 `tests/harness/test_submission_recovery.py`（6项）。覆盖错误原局拦截、流期层级不匹配、未知时辰、每日流日、旧证据、短引用在压缩与恢复后的稳定性、三次失败停止、同批次工具应答完整、跨用户读取保护和继续原记录提交。
- 修改文件的 Ruff 检查与格式检查通过，`git diff --check` 通过。

验证采用离线模型与日志回放；未调用真实模型重新生成解读。运行中的网页后端未启用热重载，需要重启加载修改。
