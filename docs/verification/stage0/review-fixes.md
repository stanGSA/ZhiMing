# 阶段 0 复核修复

日期：2026-10-20。对提交 `753ac8f`（阶段0修复与DeepSeek验证归档）做独立复核后，修复复核发现的问题。复核以该提交相对父提交 `3f70de8` 的 diff 为范围；本页只记录修复，不改动阶段0原验收材料与真实模型批次结果。

## 发现与修复

| 级别 | 问题 | 修复 |
| --- | --- | --- |
| 高 | 画像 `tz` 只要求值出现在原话中，非 IANA 值（如 `PST`）可以写入；每轮刷新日历时 `ZoneInfo` 抛错，所有后续轮次失败，CLI 启动失败，CLI 中的危机消息也得不到安全回应（父提交同场景返回危机支持） | `tz` 与 `consultation_tz` 写入前都校验有效 IANA 时区（含 `America` 这类目录名）；日历刷新跳过无效的旧值并回退到下一候选；`turn()` 先做安全检查再刷新日历 |
| 中 | 每日运势未传 `tz` 时不再采用对话中确认的咨询时区，也不再追问；画像没有 `tz` 时日历按上海、运势按出生地时区计算，出现日期错位 | 每日运势按“对话确认的咨询时区 → 画像咨询/出生时区 → 出生钟表时区”取时区；若与日历基准时区不同，返回 `calendar_timezone_mismatch`，要求先把该时区保存为 `consultation_tz` 或 `tz`，日历刷新后再按新日期调用；日历时区变化时重新解析“今天/明天” |
| 中 | 到期清理先删业务记录（含清理期限）再删 trace；删 trace 失败时请求报错、trace 永久遗留且不再重试，后台清理任务随异常退出 | 先删 trace，再删业务记录与期限；单个身份失败只记日志，期限保留到下一次重试；请求前与后台清理的异常都被隔离 |
| 低 | `scripts/compare_layers.py` 固定日期会被每轮刷新覆盖，结果仍标注固定日期 | 支持逐轮刷新的版本改为固定运行时时钟，旧版本保持原写法 |
| 低 | 网页入口已检查安全后，`turn()` 又把同一消息交给分类模型，模糊表达调用两次 | 网页调用 `turn(..., safety_checked=True)`，同一消息只分类一次；CLI 不变 |
| 低 | 安全确认要求逐字一致，带引号复制或半角逗号无法解除暂停 | 比较时忽略全半角、空白、外围引号与句末标点；附加请求仍不解除 |
| 低 | 每个请求都补登旧 `web-` 记录（扫描六张表） | 补登只在启动时执行；升级前记录仍从首次启动起有12小时宽限 |
| 低 | 对话原文含 `America/Argentina` 这类时区目录名时，咨询时区解析抛 `IsADirectoryError` | 视为无效时区忽略 |

阶段0验收文档末句“也未创建PR或推送远程”写于推送前；分支随后已推送并用于本次复核。原文档按历史材料保留，不作改写。

## 测试

`tests/test_stage0.py` 新增7项回归，均在修复前的 `753ac8f` 上失败、修复后通过：

- 非 IANA `tz` 被拒绝；数据库中已有无效 `tz` 时运行时仍可启动，危机消息仍得到支持回复
- 画像未存出生时区时，每日运势先要求保存 `tz`，日历刷新后“今天”与计算时区一致
- 对话说明“按北京时间”但未保存时，先要求保存 `consultation_tz`，再按北京时间日期计算
- 删除 trace 失败时保留清理期限，下一次请求重试并清理干净
- 网页一条模糊表达只调用一次安全分类
- 带引号、半角逗号与空格的确认语可以解除暂停
- `compare_layers` 固定日期在一轮对话后仍然有效

`tests/test_web.py` 中两个替换 `turn` 的测试桩改为接受关键字参数，断言不变。

复核环境全量收集646项（原639项加新增7项）：634项通过；其余12项为缺少 `de440s.bsp` 的环境问题（11个独立星历交叉检查在准备阶段找不到文件，`doctor` 仅该必需数据项不满足），与修复前在同一环境的结果一致。`tests/test_stage0.py` 23/23、`tests/test_web.py` 11/11 通过；Ruff lint、format 检查与 `git diff --check` 通过。
