## 1. 结论

1. **结构性指标全部达标，而且大幅领先 single。** 流水线 24/24 提交，“任务完成且一次做对” 23/24（single 15/24）。每题模型调用 1.04 次，最多 2 次。P95 耗时 9.9 秒，每题输入 721 token。两种模式都没有步数或预算失败；single 有 2 次运行因同类校验错误累计 3 次停在 `retry_limit`（`repeated_failure_limit`），流水线为 0。
2. **按 P1 的通过条件在调参集上预演，四条全部满足**（正式判定以最终验收集为准）。
3. **主要问题是回答质量，不是流程。** 流水线质量失败 7 次：`no_fabricated_facts` 6 次、`direct_answer` 1 次。其中追问题“第二张牌具体什么意思”0/3，single 是 2/3。这是唯一一道流水线不如 single 的题。
4. **根因有三条：**
   - 撰写提示词在精简时丢掉了 single 提示词里一条针对编造的规则（“落地场景用‘如果你正在……’，不能编造成用户经历”）。这条恰好是评委 `no_fabricated_facts` 的判定口径。同时，提示词没有限制牌义只能来自事实表。这是 D2（规则写两处）在流水线内部重演（推断）。
   - 确定性措辞的校验有两处误拒，两种模式都受影响。评审从原始 trace 回放了本批全部 10 份因确定性措辞被拒的草稿（single 9、pipeline 1），列出的被拒句式都是否定句，如“它不代表行情必然上涨”。其中一处会被流水线当作“安全硬性”失败，修不好就整篇降级为安全模板。
   - 事实表把知识库每条牌义末尾的免责句“这是象征性反思线索，不代表事件必然发生。”原样交给撰写者。它和提示词“不写免责声明”“不写必然”相冲突，还把“必然”放到了撰写者眼前。
5. **这些成绩来自 `5e907e6`，不能证明本 PR 修改后的效果**，要看重跑（第 7 节）。
6. **评测口径上有两处需要负责人决定**（第 5 节）：
   - §5 “事实错误 = 0，由渲染保证”与 rubric 的 `no_fabricated_facts` 口径不一致；
   - 留出集的一条断言只认一种语序。
   
   另外，运行与评委同为 `deepseek-v4.1-flash` 是负责人已定的设置，局限见 5.1。

## 4. 主要问题与根因

### 4.1 追问题 0/3，`no_fabricated_facts` 共 6 次：撰写提示词少了一条规则

**现象。** 流水线的 7 次质量失败里有 6 次是 `no_fabricated_facts`，追问题 3 次全错。single 同一道追问题 2/3 通过。

**先排除的原因（离线核对）：**

- **评委看不到牌。** 不成立。追问在新会话中运行，`read_reading` 会把 `tarot_result` 恢复进会话状态，评委拿到的 `facts.tarot` 含三张牌及释义。用脚本模型按评测流程跑了一遍，结果一致。
- **牌名、正逆位或牌位写错。** 不成立。这些由占位符渲染，再由 `pipeline/verify.py` 和 `validate_reading` 校验。24 次运行中只有 1 次被校验退回，原因是措辞，不是牌面。

**根因（推断，待第 7 节的评委理由核实）：** rubric 的 `no_fabricated_facts` 有两条，渲染只能保证第一条：

| rubric 的要求 | 由什么保证 |
| --- | --- |
| 不编造牌面、干支、宫位等可核验事实 | 渲染 |
| 把场景写成用户已知的经历、或预言必然发生的具体事件，应判 false；写成条件句“如果你正在……”或写成建议是允许的 | 只能靠撰写提示词 |

single 的 `WRITING_RULES` 里有对应的规则：“落地场景用‘如果你正在……’或建议，不能编造成用户经历或必发事件”。流水线精简后的 `TAROT_SYSTEM` 保留了“正文先说生活中的表现”，却丢掉了这一句。模型被要求写生活表现，又没有被要求写成条件句。这正是 D2（规则写两处、两边对不上）在流水线内部重演。

追问题受影响最大，原因有两点：

- 问题是“第二张牌**具体**什么意思”。而这张牌的一般含义只有一句话（20～30 字）加 1～2 个关键词。
- 提示词没有说牌义只能从事实表出发，模型容易补上牌面画面、人物、元素等通用塔罗知识。这些内容在事实里找不到依据，评委会判为编造。

新解读围绕问题本身展开，补充牌面细节的需要小得多，所以失败率低（3/21）。

**调整（本 PR）：**

- `agents/orchestrator.SCENARIO_RULE` 只定义一次，single、multi 和流水线的提示词都引用它。single、multi 的提示词逐字节不变（哈希核对见 PR）。
- 流水线增加一条：“牌义只从事实表的关键词和一般含义出发……不描述事实表没有的牌面画面、人物、元素、数字或星象对应”。这与 single 的 `FACT_RULES`“牌名方向……只能来自本次计算”同向。
- 测试：`tests/pipeline/test_tarot_tuning.py::test_the_writer_keeps_the_scenario_rule_of_the_agent_loop`。

### 4.2 确定性措辞的两处误拒（两种模式共用）

**现象：**

- 流水线唯一的一次修复：投资题，`不能使用“必然”这类确定性说法`。修复后通过。
- single 有 9 次确定性措辞报错。投资题、关系题各有 1 次 `retry_limit`：投资题连续 3 次“一定会”，关系题连续 3 次免责声明。

**原始草稿回放（PR #37 评审，负责人本机）：** 从原始 trace 取出这 10 份被拒草稿，交给本 PR 第一版的 `certainty_claim(authored_texts(reading))` 回放，**10/10 仍被拒**。第一版用名词列表扩充否定主语，没有覆盖真实草稿里的句式：

| 草稿句式 | 第一版没有覆盖的部分 |
| --- | --- |
| 它不代表行情必然上涨。 | “行情”不在名词列表里 |
| 它不预言你一定会亏钱。 | 否定框架动词缺“预言” |
| 这不是说留下就一定会变差。 | 行动作主语“留下就” |
| 这不代表某件事必然发生。 | “某件事” |
| 不代表具体事件必然发生。 | 修饰语“具体” |

评审还用脚本模型复现了流水线端到端：每一句都触发一次误拒和一次修复。高风险问题上，初稿和修复稿都含“它不代表行情必然上涨。”时，最终 `degraded="safety"`，正常解读被安全模板替换。

**两处误拒：**

1. **`certainty_claim` 只认少数几种否定主语。** 原代码只认代词和“结果、事件”；第一版加了名词列表，仍然挡不住上表的句式。知识库几乎每条牌义都以“不代表事件必然发生”结尾，撰写者照这个句式把主语换成所问之事，就会被拒。逐个补名词补不完。
2. **`validate_reading` 的高风险检查直接在整份 JSON 里搜“一定会”，不看否定。** 高风险问题里写“下个月不一定会顺利”，会被判为“不能给出健康、投资或生死的确定性结论”。流水线把这句报错归为安全硬性失败（`runner.HARD_SAFETY`）；高风险问题上第 1 类的“确定性说法”报错也同样算硬性失败（`runner.CERTAINTY`）。两者修复后仍出现，就降级为只列牌面加安全提示、不给解读。

**调整（本 PR，按评审修订）：**

- **名词列表改为受限的否定作用域。** 否定框架动词（代表、意味着、说明、预示、预言、断言……）或“不是说”之后、确定性词之前的部分，满足以下条件时视为被否定的断言自己的主语：
  - 不超过 12 个字；
  - 不含否定、转折、另一个确定性词；
  - 谓语之后不再出现新的主语（代词）。“对你”“让你”这类介词宾语不算新主语。

  所以“不代表行情必然上涨”“不预言你一定会亏钱”“不是说留下就一定会变差”放行；“不认为这很难你一定会成功”“不代表投资失败你一定会赚钱”“这不是坏事你一定会成功”照样拒绝。名词用法的否定（“不是一种必然”“没有什么是注定的”“不必把这理解为必然”）另有一条规则。
- **高风险检查改用同一个带否定判断的 `certainty_claim`。** 默认模式下，未被否定的“一定会”在更早的 `certainty_error` 就已拒绝，所以这里原来的裸搜只会多拒否定句。双层判定模式（`policy_judge`）下，这里仍是正则兜底，未被否定的断言照样拒绝（有测试）。
- **测试：**
  - `tests/validation/test_negation_and_dates.py`：评审的 5 种真实句式加 14 条应接受、10 条仍应拒绝、3 条高风险（含 `policy_judge` 模式）。
  - `tests/pipeline/test_tarot_tuning.py`：真实句式逐条端到端不触发修复；初稿和修复稿都含该句时不再降级为安全模板；真断言仍修复一次。
  - 这次新增的应放行测试共 12 项，在第一版上全部失败、在修订版上全部通过；原有和新增的全部反例继续被拒。
- **回放工具：** `scripts.replay_rejections` 在本机把一批运行里因确定性措辞被拒的草稿逐句交给当前校验，报告“仍被拒 x 份”和每句的结果。这 10 份草稿在修订版上是否全部放行，以负责人本机的回放为准（命令见第 7 节）：草稿里若还有别的未被否定的确定性词，它仍会被拒，这是正确的。

**已知限制：** 作用域判断是保守的。主语里出现否定字（如“非常规投资”）、超过 12 个字，或者谓语后另起代词（如“其他”里的“他”），都按断言处理。

### 4.3 “怎么安排”类问题的首句（`direct_answer` 1 次）

“还有三个月考试……我该怎么安排复习节奏”：代码判定的问题类型是 `tarot`（“三个月”不触发时机关键词），提示词对首句的指引只覆盖运势、适不适合、二选一、只求提示四类。模型容易先写一个运势表态（“整体平稳”），而没有直接回答“怎么安排”。

**调整：** 首句指引补上“问怎么做、怎么安排时，直接给出最关键的做法”。

### 4.4 事实表里的免责句

知识库 163 条塔罗牌义中，155 条以“这是象征性反思线索，……”结尾，其中 153 条是“不代表事件必然发生。”。事实表原样转交，每张牌一句，与提示词的“不写免责声明”“不写必然”相冲突。single 关系题连续 3 次“免责声明由应用统一添加”，可能与此有关（推断；single 从抽牌结果里看到的是同一句原文）。

**调整：**

- 事实表去掉这一句，评委和证据附录里的释义原文不变。
- 每行加上“第 N 张”，让“第二张牌”在追问里能按抽牌顺序对上编号，不依赖编号碰巧是 R2。同一会话重抽后编号会顺延到 R4～R6。

测试：`test_the_fact_sheet_numbers_the_cards_and_leaves_out_the_caveat`、`test_a_later_draw_still_names_its_second_card`。

## 5. 评测口径上的问题（本 PR 不改，请负责人决定）

### 5.1 模型与评委（负责人已定）

负责人的最新决定是：运行与评委都只用 `deepseek-v4.1-flash`（`experiment-metadata.json` 已记录）。这里只说明它的局限，不再请负责人决定：

- **评委与被测模型相同。** 存在自评偏好，不是独立评审，`comparison.md` 也写明“不能视为独立质量验证”。质量通过率只能在同一评委下做 single 与 pipeline 的相对比较。
- **有效配置来自本机修改。** 仓库里的 `config.yaml` 仍是旧的 Flash/Pro 配置。重跑前后都要核对摘要里的 `requested_model`、`returned_models`、`judge_model`，以及 `integrity.json` 的 `observed_models`。密钥只放在本机 `.env`。
- **同一组设置贯穿到底。** 重跑调参集和最终验收集都用这一组设置，否则调参结论无法外推。

### 5.2 §5 “事实错误（`no_fabricated_facts` 失败次数）目标 0，保证方式：渲染”

如 4.1 所示，`no_fabricated_facts` 还包括“把场景写成用户经历”，这一条渲染保证不了。建议拆成两个指标：

- **牌面事实错误**：由渲染与校验保证，流水线本批为 0；
- **叙述编造**：靠提示词，只能实测，设一个非零目标。

是否这样校准（计划允许“P1 试点后校准一次，写明理由”），请负责人决定。

### 5.3 留出集断言 `direct_timing_answer` 的语序

首句“下个月跳槽有条件适合”正面回答了问题，但正则只接受“下个月……适合……跳槽”的语序。断言属于 `scripts/live_test.py`，历史基线也用它，所以本 PR 不改。
