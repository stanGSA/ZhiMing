## 通过标准

以下沿用现有套件的逐题严格判定和既有专家／审校关口，不降低阈值。失败被 guard 拦住后修正，可以记录为最终恢复，但仍不能改成“中途零错误”。

| 项目 | 通过要求 |
| --- | --- |
| 基础场景 | 17/17 按冻结后的断言通过；如修订断言，同时保留旧口径结果 |
| baseline | single、multi 各 20 个不同题目均完成工程与质量判定，严格综合 20/20；服务或评分不可用不能当作内容通过 |
| 专家报告 | 按现有口径排除 needs_input 后合规率 ≥98%；另报包含中断尝试的分母与首次通过率 |
| 审校 | 漏拦率 ≤10%，过度干预率 ≤5%；报告模型不可用次数 |
| 事实与引用 | 逐题检查有效引用与本次计算归属，未知时辰不输出宫位／四轴断言；完整 baseline 中不得出现未拦截的此类错误 |
| 独立评分 | 评分器可单独配置，使用不同厂商模型并记录身份；没有可用独立评分服务时，该项保留未验收 |
| 工程回归 | 对应离线测试、全量 pytest、Ruff 与数据完整性检查通过 |

这些标准是本任务完成条件；不替代知识库审核、完整第七周评估或整个产品的发布验收。
