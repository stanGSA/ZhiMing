## 八字流水线（`pipeline/bazi.py`）

**意图。** 问题里有八字、四柱、命盘、日主、十神、大运、流年、流月、起运、交运等词，且没有提别的体系，就由八字流水线处理。三种问题类型（`requirements.bazi_question_type`）：

| 类型 | 判断 | 计算 |
| --- | --- | --- |
| 原局 `trait` | 其余 | `compute_bazi` |
| 大运概览 `dayun` | 只问起运、大运、首运，没有问一段时间（与 agent 循环的 `dayun_overview` 同一判断） | `compute_bazi`，事实表列各步大运；不补算流期 |
| 时机 `timing` | 读得出时间范围，或问了运势、流年等 | `compute_bazi` 加 `compute_bazi_period` |

时机题的粒度由代码按范围定：10 天以内流日，一年以内流月，再长流年。交回 agent 循环的：追问已保存的解读、更正出生资料、合婚紫微神煞等计算器没有的技法、同时问别的体系的问题。

**事实表。** 编号后面是代码渲染的文字：

| 标签 | 例子 |
| --- | --- |
| 日主 | 日主丁火 |
| 四柱 | 月柱癸巳（天干癸为七杀）；日柱丁未（日主所在） |
| 大运 | 1997年12月10日起运，首步大运壬辰（1997年交运）；第3步大运庚寅（2017年交运，2027年换下一步）；第3步大运庚寅天干庚为正财 |
| 流年、流月、流日 | 流月戊戌（十神伤官；2026年11月1日00:00至2026年11月7日17:52，北京时间） |
| 流期与原局 | 流月戊戌与本命月柱癸巳天干合（同上时段） |

- 流日的范围里，同一个流年、流月只列一次，时段写整段（`merged_spans`），不会每天重复一遍；
- 先列全部流年流月流日，与原局的关系在剩下的名额里列（共 48 条）；
- 五行计数、当前所在大运、是否真太阳时、出生时间未知只有三柱等写在事实表前面的说明里，不作编号。

**撰写。** 提示词 `compose.BAZI_SYSTEM` 与星盘同一结构：干支、十神、大运、流期和日期只写编号；流月按节气换月，不写成公历整月；喜用神程序不算，要谈只能据月令和五行计数推断并写明依据。

## 资料检查与追问（P3.1）

需求表（`requirements.REQUIREMENTS`）新增三行：

| 类型 | 必需 | 要确认的情形 | 执行点 |
| --- | --- | --- | --- |
| 原局 | 出生日期、地点、时间（未知须说明，只排三柱） | 海外出生用不用真太阳时；新疆出生是北京时间还是新疆时间；农历是不是闰月；时辰未知且当天交节，补时间或确认展示候选 | `birth_ready` / `pipeline.birth`；`compute_bazi` 的 NeedsInput |
| 大运 | 加性别 | 真太阳时修正跨节气：确认按物理时刻起运 | `Bazi.compute` 问性别；`compute_bazi` 的 NeedsInput |
| 时机 | 加时间范围（流月流日 ≤ 366 天，流年 ≤ 3660 天） | 区间时区：说明了就用；北京时间出生默认北京时间；其余追问 | `asked_range`；`compute_bazi_period` 的 NeedsInput |

- 计算器自己的确认逻辑原样复用：NeedsInput 变成模板追问，结束本轮；下一条消息先按原来的 `input_evidence` 函数读答案，再从计算处继续。答案怎么读：补出生时间用 `clock_in`；真太阳时用 `solar_time_choice`（计算器自己读）；新疆钟表时区用 `xinjiang_birth_clock`（同上）；闰月看“闰X月 / 普通月”；时辰未知仍不知道看“候选 / 两种 / 仍不知道”；物理时刻起运看“物理时刻起运”；性别用 `gender_evidence`。
- 性别只认用户说自己的话（“我是女生”“性别男”），“女朋友”“男同事”不算。读到后用计划调用 `update_profile` 写入画像，证据是用户原话。
- 八字一个解读最多问 3 次（星盘 2 次）：文字给出生资料时可能要先问地点、再问时间、再问真太阳时。
- 区间时区**没有**沿用星盘的出生地默认（负责人 2026-11-07 的决定只针对 astro_timing），海外出生又没说明时区就追问。

## 消息里用文字给出生资料（`pipeline/birth.py`，星盘和八字共用）

r4 复核 §4 列为主集前必须完成。以前这类消息整条交给 agent 循环，现在由代码处理：

1. **日期和时间**用 `plugins.context.inferred_birth` 读（与计算器的出处检查同一读法；把其中按分句找出生日期的部分抽成 `birth_date_mentions`，行为不变）。只认一个跟“出生/生于/生日/生辰”连着的完整日期；没写时间的先存日期，时间由计算器追问。
2. 用计划调用 `update_profile` 存出生日期，证据是用户这条消息；说了“不知道出生时间”同样存 `time_known=false`。
3. **地名**从“出生在X / 生于X / 在X出生 / X出生 / 出生地X”里取，再用 `birth_place_mentioned` 排除现居地。依次试原文、截到“市”或“县”、去掉省名，用计划调用 `resolve_location` 解析；括号里写的国家（“纽约（美国）”）作为限定一起传。
4. **同名地点必须追问**，列出候选的国家和省州；回答里写到的国家或省州原样传给 `resolve_location`，由它自己的校验确认，代码不替用户选。没找到地名就问城市。
5. 地点解析后，后面的事和出生表单一样：时间缺了、新疆钟表时区、海外真太阳时都由计算器的 NeedsInput 追问。
6. 读时间范围前先去掉出生日期和后面的时刻（`without_birth`），所以“我1990年3月5日出生，看看下个月”不会把出生月份当成范围。

**农历生日只用于八字。** “农历2023年闰二月十五 10:00”按原文传给 `compute_bazi`，闰月由计算器追问；换算出的公历日期只留在本次解读里，不当作用户写的公历生日存进画像。用文字写的时间（“早上10点”）要求紧跟在农历日期后面、在同一分句里：`BaziPlugin.validate` 为此加了 `stated_lunar`，这是出处检查的一处放宽，守卫见下。没写时间的，追问时请用户把日期和时间连在一起再写一遍。

**仍交给 agent 循环的：**

- 没有完整日期的出生（“我是1990年3月出生的”），共用的 `question_range` 会把月份读成范围；
- 与已保存出生资料不同的（属于更正）；
- 网页出生表单已绑定到本次请求时，只用表单。

## 闭集的放宽与“仍须拒”

八字闭集里认作“没有断言”的写法，以及对应的守卫（`tests/pipeline/test_bazi_closed_set.py`、`tests/pipeline/test_typed_birth.py`）：

| 放宽 | 接受 | 仍须拒 |
| --- | --- | --- |
| 否定一个错的值 | “日主不是乙木，而是丁火”“首步大运不是X，而是壬辰”“流月X与年柱Y并不相冲”（确实不冲）“命局里没有X”（确实没有） | 同句另一个错值（“……而是乙木”“……与日柱也相合”）；先否定后肯定；外层否定（“不能说日主不是乙木”“不可能日主不是乙木”“不能说……不冲”）；程度词（“日主根本不是丁火”“完全不是”“不完全是乙木”）；双重否定（“并非不是”“不是不是”“不是不冲”）；转折后重新肯定（“不是乙木，但其实是乙木”“不冲，但其实相冲”）；否定真实的值（“日主不是丁火”“命局里根本没有X”而原局有） |
| 否定推论 | “并不是丁火日主都外向” | 推论之外又否定了真实的值 |
| 藏干的十神 | “地支藏干里有X”（藏干里确有） | 藏干里没有的十神 |
| 农历日期后的文字时间 | “农历2023年二月十五早上10点出生” | 时间在另一句、写“大约”、时间不同、日期不同、时间属于后面另一个日期、时间在另一条消息、没写时间 |

十神按句中最近的主语核对：“月柱X为……”“流月X……”“第N步大运X……”“X透出……”。没有主语的十神只要求出现在原局、大运或这段时间的流期里。
