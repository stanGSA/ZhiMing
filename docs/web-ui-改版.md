# 网页界面改版

日期：2026-10-23。依据画布样稿把原先“侧栏 + 卡片 + 主题换色”的单页界面，改为一个入口页、一个问道首页和六个功能页。每一页按其主题单独设计，按钮形制也随主题变化；功能、接口和校验规则沿用原有实现。

## 页面与风格

| 地址 | 页面 | 风格 | 主按钮 |
|---|---|---|---|
| `/`、`/login` | 入口 | 玄金罗盘：黑漆底、金线罗盘（二十八宿、二十四山、后天八卦、天心十道） | 金色匾额双框「入内」 |
| `/ask` | 问道 | 千里江山青绿：绢色底、石青石绿山峦、朱砂印；六术目录 | 石青方印「问」 |
| `/bazi` | 八字 | 朱漆描金：四柱牌匾（十神、藏干、纳音）、算珠式五行、大运时间轴 | 朱漆描金边 |
| `/astro` | 星盘 | 天文台：按上升定向的本命盘、宫位、相位线、等宽度数表 | 发丝细线框 |
| `/tarot` | 塔罗 | 暗紫鎏金：拱顶牌框、玫瑰窗，按实际抽牌显示牌面与正逆位 | 拱窗形 |
| `/name` | 姓名 | 碑拓金石：米字格大字、康熙笔画、传统五格剖象括号图、三才 | 朱文印章「推演」 |
| `/dream` | 解梦 | 庄周梦蝶：月雾、线描蝴蝶、信笺式记梦、醒来感受 | 月白圆角 |

页面不加载外部字体或脚本，遵守原有内容安全策略（`style-src 'self'`，无内联样式）。中文字体按系统字体回退：宋体类用于正文与标题，楷体类用于姓名页的大字。

## 接口变化

- `ChatInput.system` 增加 `name`、`dream`、`daily`，消息末尾注明“本次希望使用姓名五格／解梦／每日运势来解读”。只有问道、八字、星盘、运势会附带出生资料；塔罗、解梦、姓名不发送。
- 离线演示只会抽塔罗，因此解梦、姓名、运势在离线演示中返回 `demo_unsupported` 提示，不再用牌面代答。
- `PUT /api/birth`：保存生辰档案，各页共用；生辰改变时清除旧命盘。
- `POST /api/name`：按 `plugins.name.wuge.analyze` 直接计算康熙笔画、五格、三才，不调用模型；有多种写法的字返回备选，由用户选择后重算。
- `POST /api/almanac`：按 lunar-python 给出某日的年月日干支、农历、节气与物候、日元素及知识库中的配色说明、本周流日；填写了出生日期与地点时，按日主推算各日十神。流日取当地正午所在日柱。
- 会话列表 `history` 改由 `Store.reading_history` 提供，额外带 `systems_used` 与 `created_at`，供足迹与梦境日记显示；交给模型的 `recent_readings` 不变。
- 会话仍有效时访问 `/` 会 303 跳转到 `/ask`；入口页设为 `Cache-Control: no-store`，避免浏览器缓存旧的入口。

## 范围与限制

- 账号登录与跨设备同步尚未实现。入口页的“账号登录”页签明确标注“筹备中”，输入框不可用；可用的是访客入内与离线演示。
- 每日一牌与行运相位仍来自完整的运势解读（需真实模型），在详解后显示；页面直接计算的只有历法部分。
- 本次未在真实模型下做端到端解读，只验证了离线路径和接口。

## 验证

- `tests/test_web.py` 新增 6 项：各页地址与入口跳转、不含内联样式；新体系的提示语与出生资料范围；离线演示不以牌面回答解梦、姓名、运势；`/api/name` 对“陈知远”得出天格 17、人格 24、地格 25、外格 18、总格 41、三才金火土，并拒绝非汉字与无关写法；`/api/almanac` 对 2026-10-22 得出丙午年、戊戌月、己巳日、九月十三、次日霜降，按 1994-03-18 08:30 杭州西湖区的日主癸水得出当日七杀及整周十神；生辰保存与命盘失效。
- 在本机用 Chromium 检查 8 个页面：1440 与 390 像素宽度均无横向溢出、无脚本错误。离线演示下走通：八字排盘、星盘绘制、姓名推演与写法选择、三张牌抽牌与解读、问道首页解读与近来所问、足迹回看、切换运行模式、清除记录、解梦与运势的离线提示。
- Ruff 检查与格式检查通过。完整测试中，`test_doctor_week1_required_checks` 只因本机网络策略无法下载 JPL `de440s.bsp` 而失败，与界面改动无关；CI 会下载该文件。

## 第二轮：对话窗与塔罗翻牌

针对“与模型对话的入口太隐蔽”与“塔罗缺少交互感”，只改前端，接口与校验不变。

- **对话窗**：问道、八字、星盘、塔罗、姓名、运势六页统一为带边框的对话窗：页眉（印章、标题、连接状态）、左右分列的问答气泡、底部常驻输入框与发送键，输入框随文字增高。对话窗与解读面板并排，放在命盘、星图或日历正下方；宽屏时对话窗吸附在视口内，滚动阅读长解读时仍可发问。配色、边框与圆角沿用各页主题，由 `--dialog-*`、`--bubble-*` 变量控制。解梦页的记梦信笺未改。
- **浮动入口**：对话窗不在视口内时，右下角出现「问 · 对话」按钮，点按回到对话窗并聚焦输入框；塔罗页尚未抽牌时回到“所问”。
- **问道**：去掉原先压在山峦上的「所问」长卷与「问」字大印，提问改在“问答”区的对话窗内完成；六术、近来所问、生辰档案保留。
- **生辰折叠**：八字、星盘、运势的生辰表单移到标题下方，折叠为一行摘要（如“公历 1994-03-18 08:30 · 中国 · 浙江省 · 杭州市 · 西湖区 · 女”）。未填写时八字、星盘默认展开；排盘或保存后自动收起并滚到命盘。运势页的「填写生辰」与缺资料提示会展开它。
- **塔罗**：步骤条（选牌阵 → 写下所问 → 从牌堆选牌 → 翻牌见意）。点「洗牌抽牌」后，78 张背面朝上的牌收拢再展开成扇形，逐张点选，选中的牌飞入牌位；选满后发问，牌以背面落位，轻触逐张翻开（或「全部翻开」）。全部翻开前，牌意与回答保持模糊。之后的追问在对话窗进行；刷新或回看历史时直接显示牌面。在对话窗或建议问题里先写问题，会填入“所问”并开始选牌。
  - 一轮的状态：选满时就固定本轮的问题、牌阵与所选位置。回复里没有牌面（知命先追问补充信息，或请求出错）时，这一轮保持打开：牌位留着、牌堆不再展开，在对话窗里的回复直接发送，并带上同样的牌阵与位置；服务端对尚未完成的记录也以最近一次的所选位置为准。打开着的一轮（原问题、牌阵、所选位置）保存在浏览器会话上，由 `/api/session` 的 `tarot_round` 返回；刷新页面后据此恢复，回复仍直接发送。得到牌面、开启新对话或清除记录时清空。
  - 每次重新起问都换一个轮次编号，并取消还在飞的牌。动画回调先核对编号，旧一轮的回调不会再发请求；重新起问、开启新对话、切换模式、清除记录走同一条重置路径。
  - 从足迹打开某条记录、或刷新后恢复记录时，“所问”显示该记录自己的问题（与足迹列表一致）；尚未发送的草稿另存，重新起问、开启新对话或切换模式时放回；清除记录时一并清空。
- **选牌决定牌面**（审核后选定方案 A）：会话种子仍按 `tarot-sha256-v1` 排出整副 78 张的顺序，相当于洗好、背面朝上摊开；用户点中的位置（`picks`，0–77，按牌位顺序）决定抽到哪几张。牌扇下方写明“你点中的位置，就是抽到的那张牌”。
  - 网页：`POST /api/chat` 增加可选的 `picks`，只用于塔罗，须与牌阵张数相符且互不重复，否则返回 422。每次请求都重设，选择不会带到之后的问题。
  - 会话：`Session.pending_picks` 由 `start_reading` 写入本次记录的状态并清空，只用一次；塔罗专家子会话继承同一记录的 `picks`。抽牌工具拒绝与所选张数不符的牌阵。
  - 结果：抽牌结果与入库的 `tarot_json` 带 `picks`；`draw_tarot(spread, question, seed, picks)` 可完全重算，`scripts/gate_evidence.py` 的回放校验已传入 `picks`。不带 `picks` 时结果与原来逐字节相同，命令行、评测与历史记录不受影响。

验证：新增测试覆盖 `picks` 的取牌、非法输入、单代理与塔罗专家两条路径、只用一次、牌阵不符被拒、网页接口校验与入库重算，以及澄清后的回复沿用同一条记录并以最近的选择抽牌。`tests/test_web_browser.py` 用真实 Chromium 跑六条回归：澄清后直接继续同一轮、澄清后刷新页面仍能继续、最后一张牌飞行中重新起问不发请求、足迹切换时“所问”随记录、未发送的草稿在看完记录后恢复、清除记录时草稿一并清空；每条在对应修复前的代码上都会失败。测试等待 `/api/chat` 的实际响应与页面退出忙碌状态，不以对话气泡数量判断完成（思考中的占位也是回答气泡）。CI 只在 Ubuntu 上安装 Chromium 运行它们，其他环境跳过。浏览器中点选第 61、9、35 位后，入库记录的 `picks` 与之相同，按种子与 `picks` 重算得到同样三张牌，且与不选时的最上面三张不同。在本机用 Chromium 检查 390、768、1100、1440 像素宽度七个页面均无横向溢出、无脚本错误；离线演示下走通问道发问、八字排盘与发问、星盘绘制与发问、塔罗单张与三张的选牌—翻牌—追问、刷新后牌面保持、选牌中途开启新对话、运势发问。本环境的网络策略拦截了 Unihan、geonamescache 与 JPL `de440s.bsp` 数据下载，姓名推演只检查了空状态。完整测试 786 项通过；91 项因缺上述数据文件失败或报错，与未改动代码上失败的 91 项完全相同。

## 第三轮：布局、排版与动效

日期：2026-11-22。只改 `web_static/`，接口、校验与后端不变。

- **栅格**：`.dialog-band` 改为「盘面 / 解读」同在左栏、对话窗占右栏全高并吸附，宽屏下右栏不再留出大片空白；解读正文行宽限制在 46em。塔罗页 `main` 由 `overflow: hidden` 改为 `overflow: clip`，否则对话窗无法吸附。
- **回答气泡**：已整理进解读面板的长回答（`submit_reading`）在气泡中只显示前 5 行，附「展开全文」与跳转到解读面板；其他回复照常完整显示。
- **推演轨**：思考气泡改为六步（问意、排盘、专家、合参、核验、成文），`/api/progress` 的标签按关键词归入步骤并累积保留；「事实核对未通过，正在改写」在核验一步标朱红「退」；右上角显示已用秒数。专家与合参两步只在出现对应事件时显示。`#thinking .thinking span` 仍是唯一的 span，显示当前标签。
- **事实已核**：解读带 `evidence` 时右上角显示「事实已核」印。刚由本次请求得到的解读逐段显影后盖印；刷新、足迹回看、后台同步时直接显示，不播放。
- **排盘揭示**：八字新排盘时四柱依次升起、日柱描金、五行算珠滑入；星盘新绘制时圆环、四轴、行星、相位依次画出，未绘制时外环刻度 240 秒一圈慢转。只在盘面变化时播放，首次载入的已有命盘不播放。
- **各页收尾**：
  - 塔罗：最后一张牌翻开时，金线以弧形连起各牌拱顶（不压牌面、不碰上方提示），约 3 秒后淡去。
  - 姓名：推演后碑拓显墨、五格括号线描出、三才依次落字；五格数字由 CSS 计数器在叠层上从 0 数到结果，DOM 里的数字始终是真实值。
  - 运势：切换日期时新页从上方翻落，当日十神以印章盖下；确认生辰后十神首次算出时也盖印。页面首次显示不播放。
  - 解梦：本次解读识别出的意象从信笺方向浮入「梦中意象」栏，线描蝴蝶扇两次翅膀。
- **主题加载样式**：推演轨顶端的进行中标记按页换形（八字拨珠、星盘星轨、塔罗菱光、姓名描红、解梦月相、运势撕页），步骤节点随页为圆珠、方格或菱形；页眉连接状态点在首次取得会话前呼吸。
- **只播一次与减少动态**：所有收尾动画只在本次刚得到的结果上播放，刷新、足迹回看、后台同步直接显示最终画面。`prefers-reduced-motion` 下沿用 base.css 的全局开关关闭 CSS 动画，金线、计数、翻页等由脚本触发的部分也直接跳过。
- **竖排文字**：入口「知命」、问道标题、八字大运干支、运势黄历干支原用 `writing-mode: vertical-rl`，在缺少竖排度量的字体下会叠字；改为宽 1em、逐字换行的列。
- **逐页**：八字大运移到四柱下方；星盘行星表与相位并排、相位逐行；运势新增页头并收纳日期切换，本周流日移到黄历下方；解梦改为左「记梦 → 回信」、右「意象 + 对话」；姓名空状态高度降到 320px。
- **排版与手机**：中文标签、按钮、小标题字距由 0.3–0.6em 收到 0.12–0.2em（入口页与英文眉题保留）；提示条随主题配色；填写生辰时隐藏「问 · 对话」浮钮，760px 以下浮钮改为贴底整条。

验证：在本机用离线演示走通八字排盘与发问、星盘绘制、塔罗三张牌抽牌—翻牌—解读、姓名推演、运势切换日期、解梦、问道与入口，并逐项录屏检查上述动效；1440 与 390 像素宽度无横向溢出、无脚本错误。按 `scripts/data_manifest.yaml` 取得 Unihan 三份文件（sha256 与清单一致）后，`tests/web` 全部 108 项通过，含 Chromium 浏览器回归。姓名计数最初直接改写数字文字，`test_name_calculation_and_chosen_form_survive_navigation_and_reload` 在动画中途读到「0」而失败，因此改为叠层计数。

未做：曾设想用连线画出各体系之间的共振与张力（合参图），但解读中的 `resonances` 与 `tensions` 没有标明涉及哪两个体系，画成连线需要猜测，故不做。
